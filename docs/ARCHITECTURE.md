# 七彩布衣数字化管理系统 - 系统架构说明书 (ARCHITECTURE.md)

## 1. 架构总览

“七彩布衣数字化管理系统”是一套面向高端服装定制工坊内部使用的专业运营管理平台，专为 Windows/Mac 桌面浏览器以及 iPad 触控浏览器定制优化。

```
+---------------------------------------------------------------------------------+
|                       前端展示层 (React 19 + TypeScript)                         |
|  Tailwind CSS 4 | 响应式 iPad/PC 适配 | A4 打印引擎 | 全局快捷操作抽屉/弹窗       |
+---------------------------------------------------------------------------------+
                                      |
                                      v
+---------------------------------------------------------------------------------+
|                       业务服务与控制层 (Services Layer)                          |
|  CustomerService | MeasurementService | OrderService | InventoryService         |
|  WalletService (原子事务) | PaymentService (抽象网关) | ArchiveService           |
+---------------------------------------------------------------------------------+
                                      |
                                      v
+---------------------------------------------------------------------------------+
|                       云端持久与认证层 (Firebase Platform)                      |
|  - Cloud Firestore (Enterprise Edition): 强类型多集合数据持久化与历史快照         |
|  - Firebase Authentication: 店员/管理员 RBAC 鉴权与会话生命周期管理               |
|  - Firebase Storage: 客户照片与历史老纸质订单/量体单 PDF 扫描件托管               |
|  - Firestore Security Rules: 默认拒绝、身份绑定、只读只写流水审计控制             |
+---------------------------------------------------------------------------------+
```

## 2. 核心架构设计原则

### 2.1 资金安全与整数“分”原则 (Integer Cents)
所有涉及金额的字段（原价、折后价、应付金额、实收定金、尾款、储值余额、流水变动量等）在前端和数据库中**一律以整数“分”进行存储和计算**。
- 例：¥6,800.00 存储为 `680000`；¥0.50 存储为 `50`。
- 杜绝 JavaScript 原生浮点数在运算中产生的 `0.1 + 0.2 = 0.30000000000000004` 等致命账目误差。

### 2.2 储值“双轨制”与不可变流水 (Immutable Ledger)
储值系统由 `wallets`（当前账户余额快照）与 `walletTransactions`（不可篡改流水明细）共同构成：
1. **禁止直接篡改**：前端不可任意直接更新 `balance` 字段。
2. **原子事务处理**：任何余额增减必须通过 Firestore 的 `runTransaction` 原子操作执行。
3. **严格会计勾稽**：每笔流水必须严格满足：
   $$\text{balanceAfter} = \text{balanceBefore} + \text{amount}$$
   充值、退款记为正数，消费、手工扣减记为负数。
4. **不可物理删除**：流水集合在 Security Rules 中设置 `allow update, delete: if false`，形成可追溯的完整账务审计链。

### 2.3 订单与量体的历史不可变性 (Historical Immutability)
服装定制具有周期长、人体体型随年份变化的特点：
- 客户可以拥有无限次历史量体记录（2024年、2025年、2026年等）。
- **下单时固化量体快照**：当为客户创建定制订单时，系统不仅关联 `measurementId`，更将当时所采用的身高、净胸围、肩宽、衣长、特殊体型参数等瞬时数据完整深拷贝至 `orderItems.measurementDataSnapshot` 中。
- 后续客户即使在 2027 年更新量体，2026 年所下历史订单中的尺寸数据永远保持当时制作时的真实状态，彻底解决车间翻单扯皮问题。

### 2.4 面料库存流水管理
库存单位统一为“米（m）”。库存变动不只保存最终数字，而是必须通过 `inventoryTransactions` 记录每次采购入库、手工补库、订单生产裁剪消耗、盘点调整。低于安全库存时自动在工作台产生库存预警。

### 2.5 历史纸质档案归档体系 (免OCR高保真)
针对工坊历史上积累的几千份字迹不一的纸质老订单：
- 采用店员手机/扫描仪扫描成 PDF 或高清图片直接上传。
- 系统根据 `customerId + year`（如 2022、2023、2024）自动建立虚拟年份目录树。
- 支持按年份快速展开浏览、一键调出高保真 PDF 预览与下载。

## 3. iPad 触控与桌面双重优化

1. **触控目标规范**：所有按钮高度 $\ge 42\text{px}$，表格行高 $\ge 52\text{px}$，弹窗与侧滑抽屉设计符合平板操作手势。
2. **横屏适配**：在 iPad 常见横屏分辨率（1024x768 / 1180x820 / 1366x1024）下，采用左侧导航+顶部快捷栏+主工作区分栏架构，无多余横向滚动条。
3. **色彩与品牌**：采用哑光石板黑（Slate-900）、温润暖砂米灰（Stone-50/100）与香槟金/暗红点缀，契合高端私享定制西服店的雅致沉稳品味。
